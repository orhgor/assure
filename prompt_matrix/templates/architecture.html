Under the Hood: Why Flat Text Fails.

Chat models emit undifferentiated prose—a single string with no structure, no locks, and no proof obligations. Assure AI compiles your intent into a modular execution tree: typed JDF nodes you can edit, lock, verify, and export independently—without re-prompting the entire document.

Flat Text vs. JDF Execution Tree

Every deliverable is an AST—not a blob. Sections nest blocks; blocks carry provenance, entity bindings, and verification annotations.

  • Verification is manual

Six-Stage Execution Pipeline

From raw intent to publication-ready output—each stage produces auditable artifacts, not probabilistic guesses.

  1. ✏️

    Draft

    Intent and source files enter the vault. The engine proposes structured JDF nodes anchored to provenance.

  2. ⚙️

    Compile

    PEM dialect prompts compile to deterministic node operations—paragraphs, tables, and sections with stable IDs.

  3. 🔒

    Lock

    Critical variables and entity bindings freeze in the Truth Ledger. Locked nodes resist silent drift on downstream edits.

  4. 🛡️

    Z3 Verify

    The Z3 SMT solver checks numeric constraints and cross-node consistency—SAT means mathematically consistent.

  5. 🔍

    Red-Hat Audit

    An adversarial persona stress-tests assumptions, flags logic gaps, and attaches critiques to specific nodes.

  6. ✅

    Pre-Flight Gate

    Export blocked until Z3 passes and open Red-Hat items are resolved. Deliverables ship with a full audit trail.

Z3 SMT: Mathematical Certainty

Satisfiability Modulo Theories (SMT) lets Assure AI treat your document like a formal specification. Key metrics become symbolic variables; constraints encode relationships between them.

Example constraint set

(assert (= revenue_q3 4200000))
(assert (= margin_pct 32))
(assert (> revenue_q3 0))
(check-sat)  ; → sat  ✓ consistent

When Z3 returns sat, your locked numbers cannot contradict each other across the tree. When it returns unsat, Assure surfaces the conflicting nodes before you export—no manual cross-checking across fifty pages.

  • Truth Ledger: canonical keys map entities to values the solver can reference.
  • Node annotations: annotations.z3 records pass/violation per block without polluting export.
  • Pre-Flight Gate: unsat or open violations block .docx / PDF export until resolved.
