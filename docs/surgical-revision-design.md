# Surgical revision — node-scoped patch workflow

Status: Ticket 1 in implementation. Supersedes the freeform rewrite the refine
path performs today.

Written 2026-09-21 against `staging-local`.

## What exists, measured

The feature is not missing; it is under-constrained. Before designing anything I
checked each claimed gap against the code:

| Claim | Reality |
|---|---|
| No surgical revision | **False.** `routers/refine_node.py`, `services/refine_node.py`, `static/surgical_click.js` (570 lines), tests |
| Pronoun context missing | **False.** `compiler/aperture.py:84` extracts N-1, N, N+1 and bounds the truth-ledger subset |
| UI missing | **False.** `surgical_click.js:422` renders "Review the proposed changes, then Accept or Reject", with node selection and history |
| It runs as a rewrite | **True.** `_apply_text_to_node` overwrites `content`/`title` whole |
| No computed diff | **True.** nothing produces one |
| Only Z3 re-verifies | **True.** `refine_node.py:152` calls `verify_locks`; no entailment, no `validate_compiled_draft` |
| Prompt is under-specified | **True.** three lines: *"Return only the revised paragraph content for the target node. Preserve locked metrics from the truth ledger."* |
| No editor lock during the call | **True.** the LLM call is 3–8 s with nothing preventing concurrent typing |

So the work is: constrain the prompt, gate the output, compute the diff, render
it, and hold the target still while the call is in flight.

## Architecture

```
UI: node selected
  ├─ lock target node (pointer-events:none, opacity .6)
  ▼
POST /api/projects/<id>/refine-node
  ├─ build_aperture_context            N-1, N, N+1 + ledger subset   [exists]
  ├─ LLM, strict JSON {rationale, proposed_text}
  ├─ format-delta check                drift guard                  [new]
  ├─ Z3 lock verification              numbers against the ledger   [exists]
  ├─ entailment vs cited sources       the grounding gate           [new]
  ├─ word-level normalized diff        computed_diff                [new]
  ▼
Proposal { node_id, original_text, proposed_text, computed_diff, verification_status }
  ▼
UI: render diff, badge on status, Apply / Force Apply
  ▼
atomic replace of target_node_id only, edge whitespace restored
```

## Decisions

### 1. Verified on the request, not asynchronously

The proposal is computed synchronously on `POST /refine-node`. Measured: 3–8 s
for the model, plus the entailment call. Staging has no worker — `SUBSTRATE_ASYNC_UPLOAD`
is unset and no Celery process runs — so there is no queue to defer onto.

Synchronous is correct here because the response *is* the proposal: the user is
waiting for a diff to review, and a job id would add a polling path for a single
call. The cost is the lock in the UI, which Ticket 2 specifies anyway.

If entailment latency proves unacceptable, the fallback is to return the
proposal with `verification_status: "Pending"` and let the UI poll a second
endpoint. Not built now; the payload shape allows it without a breaking change.

### 2. Failing verification flags, it does not block

`verification_status` is `Pass | Fail | Error`, and the UI offers **Force Apply**
on `Fail`. Rationale: a claim manager may have legitimate reason to edit wording
the entailment model judges unsupported, and blocking an editor on a model
verdict is worse than showing the verdict and recording it. The decision is
logged either way.

`Error` is distinct from `Fail` and never renders as `Pass` — a verification that
could not run is not a verification that passed.

### 3. The diff is computed in the backend, word-level, normalized

The model returns `proposed_text` only. Unified-diff syntax generated by a model
is unreliable, and the backend has both strings.

Character-level diffing produces the "bloody diff" failure: a straight-to-curly
quote change or a double-to-single space marks the whole paragraph as deleted and
reinserted. So normalization runs **before** the diff:

- collapse runs of whitespace to a single space
- curly quotes to straight, en/em dashes to hyphen, NBSP to space
- then word-level Myers

The normalization is for *diffing only*. The text committed to the document is
`proposed_text` as the model returned it, with edge whitespace restored from the
original.

### 4. Format drift is checked deterministically, not by the model

The prompt forbids added headers and bullets. That is a request, not a
guarantee, so the backend counts them: headings, list markers and bold spans in
`original_text` versus `proposed_text`. A change in any count, when the
instruction did not ask for structure, sets `Fail` with the reason. This is a
deterministic check that cannot be talked out of by the model.

### 5. The source window is the node's own citations

Re-verification runs against the sources **the original node already cites**
(`node.provenance`). A node that cites nothing falls back to the aperture's
truth-ledger subset; a node with neither yields `Error`, not a pass — an
ungrounded edit is not a verified one.

## Schema

```json
{
  "name": "SurgicalNodePatch",
  "strict": true,
  "schema": {
    "type": "object",
    "properties": {
      "rationale":     { "type": "string" },
      "proposed_text": { "type": "string" }
    },
    "required": ["rationale", "proposed_text"],
    "additionalProperties": false
  }
}
```

`rationale` first is deliberate: it forces the model to state its constraint
check before producing the string.

**Provider caveat.** `strict: true` is honoured by some providers and ignored by
others. The compile path already routes across several models through litellm.
So the schema is passed as `response_format` where supported, and **always**
validated on our side: a response that is not the required object, or that
carries extra keys, is rejected and retried once, then reported as `Error`. Not
relying on the provider to enforce it is the point.

## Traps and where they are handled

| Trap | Handling |
|---|---|
| Pronoun blindspot | `aperture.py` already supplies N-1/N+1; the prompt references them as read-only |
| Bloody diff | normalization before word-level diff |
| Ghost edit collision | Ticket 2 locks the target node for the duration |
| Trailing space contagion | edge whitespace captured from `original_text` and re-applied |

## Ticket 1 — engine

1. Prompt refactor: `[ORIGINAL_TEXT]`, `[USER_INSTRUCTION]`, `[PRECEDING_NODE_TEXT]`,
   `[FOLLOWING_NODE_TEXT]`, `[SOURCE_CONTEXT]`, with the core rules and forbidden
   behaviours stated in full
2. Strict schema, validated server-side regardless of provider support
3. Format-delta drift check
4. Entailment against the node's cited sources, alongside the existing Z3 pass
5. `computed_diff` — normalized, word-level
6. `Proposal` payload on the existing route

## Ticket 2 — UI

1. Render `computed_diff` (`<del>` struck, `<ins>` weighted) rather than swapping text
2. Badge: green *verified* / amber *fails verification* / neutral *not verified*
3. Apply vs red **Force Apply** with confirmation on `Fail`
4. Atomic replace of `target_node_id`; no neighbour re-render
5. Node lock during the call
6. Edge-whitespace restoration

### CSS notes

Three specific decisions, each load-bearing:

- `white-space: pre-wrap` on the viewer — adjacent inline `<ins>`/`<del>` elements
  collapse the spaces between them in normal HTML rendering, so a one-word
  substitution renders as `patientshows` with no visible gap
- `padding: 0.1em 0` — vertical padding on an inline element forces its line box
  taller, so toggling the diff shifts every line below it
- `del:empty::after { content: "\00a0" }` — a diff that is only a deleted space
  produces an empty element, which paints nothing; without this the structural
  edit is invisible

Colour is not the only channel: deletions carry a 2px strikethrough and insertions
a 500 weight, so the states remain distinguishable under deuteranopia.

## Not in scope

- Model-generated unified diffs (rejected: unreliable, and unnecessary)
- Streaming the proposal (see decision 1)
- Applying a proposal to multiple nodes
